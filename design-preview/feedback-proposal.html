FEEDBACK & BUTTON SYSTEM · 提案

操作提醒 + 按钮体系统一

两个问题一起解决：① 复用已有的成功提醒机制（store.notifySuccess → ToastHost），把缺提醒的操作全部补齐；② 建立「实心主操作 / 描边常规 / 描边红删除」三级按钮体系，把裸文字链接从真实操作位置上替换掉。链接样式只保留给纯导航（如「查看详情」）。

A

成功提醒（Toast）设计

机制已存在（notifySuccess + ToastHost 全局挂载），本次只是补齐调用点并微调样式：右上角白卡 + 绿色圆勾，3 秒自动消失，多条纵向堆叠，与错误横幅同一区域、位于其下。

右上角 · 与 error-banner 同区域堆叠
  • 写操作成功（保存 / 删除 / 确认 / 上传 / 生成）→ 绿点成功 toast，文案「对象 + 结果」。
  • 视图切换类（打开字段草稿）→ 中性灰点 toast，与成功区分；也可选择不弹（面板出现本身已是反馈），实施前可再定。
  • 本地操作（添加/删除证据，无 API 调用）→ 同样弹 toast，复用同一机制。
  • 失败仍走现有 error-banner 红色横幅，不新增体系。
B

按钮三级体系

与「确认并正式入档 / 确认关联」同源的实心蓝只给每个区域的唯一主操作；常规操作用描边；删除类用描边红。表格与卡片内提供 sm 紧凑档。

primary · 每区域唯一主操作 实心蓝。例：确认并正式入档、确认关联、生成 AI 建议、上传文件。
secondary · 常规操作 描边灰。例：打开字段草稿、启动人工草稿、添加证据、保存字段检查、编辑、重新生成建议。
danger · 删除类 描边红。例：删除文档、删除证据、删除关联、删除清单项。二次确认仍走 ConfirmDialog。
